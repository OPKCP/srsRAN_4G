### Расчёт полосы пропускания по количеству PRB

В LTE каждый ресурсный блок (PRB) занимает **180 кГц** в частотной области (12 поднесущих по 15 кГц). Полная полоса пропускания рассчитывается следующим образом:

$$BW_{total} = N_{PRB} \times 180\ \text{кГц} + BW_{guard}$$

Где защитные полосы по краям частотного диапазона составляют примерно **10%** от общей полосы (по 5% с каждой стороны). Упрощённая формула:

$$BW_{total} \approx N_{PRB} \times 180\ \text{кГц} \times 1.08$$

Однако стандарт 3GPP TS 36.101 (Table 5.6-1) определяет точные значения полосы пропускания для каждого количества PRB:

$$BW_{channel} = 0.18 \times N_{PRB} + 0.02 \times N_{PRB}\ \text{(МГц)}$$

где $0.02 \times N_{PRB}$ — суммарная ширина защитных интервалов.

**Пример для 50 PRB:**
$$BW = 50 \times 180\ \text{кГц} + 2 \times 250\ \text{кГц} = 9.0\ \text{МГц} + 0.5\ \text{МГц} \approx 10\ \text{МГц}$$

**Пример для 100 PRB:**
$$BW = 100 \times 180\ \text{кГц} + 2 \times 500\ \text{кГц} = 18.0\ \text{МГц} + 1.0\ \text{МГц} \approx 20\ \text{МГц}$$

| Параметр | Описание | Тип / Диапазон | Значение по умолчанию |
|----------|----------|----------------|-----------------------|
| `tm` | Режим передачи (Transmission Mode). | `1`, `2`, `3`, `4` | `1` (TM1) |
| `nof_ports` | Количество Tx-портов. Для TM1 достаточно 1 порта. Для TM2/3/4 требуется 2 порта. | `1` или `2` | `1` |

> **Примечание по TM:** TM1 — одна антенна (SISO), TM2 — разнесение передачи (Tx Diversity), TM3 — циклический разнесение с запаздыванием (CDD), TM4 — пространственное мультиплексирование (Closed-loop Spatial Multiplexing).

## Раздел [rf] — RF-конфигурация

| Параметр | Описание | Тип / Диапазон | Значение по умолчанию |
|----------|----------|----------------|-----------------------|
| `dl_earfcn` | Номер EARFCN для нисходящего канала (DL). Действителен только если в `rr.conf` настроена одна ячейка. | `0` – `65535` (LTE) | — |
| `tx_gain` | Коэффициент усиления передачи (дБ). | `0` – `120` dB | `70` |
| `rx_gain` | Коэффициент усиления приёма (дБ). Если отключён — используется AGC. | `0` – `120` dB | `40` |
| `dl_freq` | Принудительное значение частоты DL (Гц), переопределяющее `dl_earfcn`. | Любое положительное число (Гц) | — |
| `ul_freq` | Принудительное значение частоты UL (Гц), переопределяющее `dl_earfcn`. Должен быть задан, если задан `dl_freq`. | Любое положительное число (Гц) | — |
| `device_name` | Семейство драйвера RF-устройства. | `auto`, `UHD`, `bladeRF`, `soapy`, `zmq` | `auto` |
| `device_args` | Аргументы драйвера устройства. | Строка | `auto` |
| `time_adv_nsamples` | Опережение передачи (в отсчётах) для компенсации RF-задержки. | `auto` или число ≥ 0 | `auto` |

> **Принудительное значение частоты (`dl_freq` / `ul_freq`):** Обычно частота вычисляется автоматически по номеру EARFCN (см. раздел "Расчёт частот DL/UL"). Однако если требуется вручную задать частоту, не привязанную к стандартным диапазонам LTE (например, для нестандартного оборудования, экспериментов или если EARFCN неизвестен), используются параметры `dl_freq` и `ul_freq`. Если задан `dl_freq`, то `ul_freq` **обязателен**, поскольку eNB должна знать обе частоты для FDD-дуплекса. Значение указывается в Герцах (Гц).

#### Пояснение параметра `device_args`

Параметр `device_args` передаётся драйверу RF-устройства в виде строки с параметрами, разделёнными запятыми (`key=value,key=value`). Набор доступных параметров зависит от типа устройства.

**Примеры для USRP (UHD):**

| Параметр | Описание | Пример |
|----------|----------|--------|
| `recv_frame_size` | Размер принимаемого кадра (байт). Влияет на производительность приёма. | `recv_frame_size=9232` |
| `send_frame_size` | Размер передаваемого кадра (байт). | `send_frame_size=9232` |
| `num_recv_frames` | Количество принимаемых фреймов в буфере. Увеличение снижает риск потери пакетов. | `num_recv_frames=64` |
| `num_send_frames` | Количество передаваемых фреймов в буфере. | `num_send_frames=64` |
| `master_clock_rate` | Частота мастер-тактового генератора USRP (Гц). По умолчанию 11.52e6 (для ≤ 5 МГц), для 75 PRB (15 МГц) необходимо 15.36e6. | `master_clock_rate=15.36e6` |
| `mode` | Режим работы: `b200` для B200/B210, `x300` для X300/X310. | — |

**Пример полной строки для USRP B210 (20 МГц, 100 PRB):**
```
recv_frame_size=9232,send_frame_size=9232,num_recv_frames=64,num_send_frames=64,master_clock_rate=15.36e6
```

#### Пояснение параметра `time_adv_nsamples`

Параметр `time_adv_nsamples` задаёт опережение передачи (в количестве цифровых отсчётов) для компенсации задержки в RF-тракте — задержки между моментом, когда eNB вставляет временную метку в передаваемый сигнал, и моментом, когда сигнал фактически излучается антенной.

**Зачем это нужно:** В SDR-устройствах (USRP, bladeRF) существует задержка между отправкой отсчётов из ПК в устройство и фактическим излучением сигнала (задержки USB/TCP, буферизация, ЦАП). Без компенсации эта задержка приведёт к рассинхронизации передачи, что особенно критично для TDD-режима и TA (Timing Advance) в LTE.

**Расчёт значения:**

$$TA_{samples} = \text{задержка\_RF\_тракта}\ (\text{с}) \times f_s$$

где $f_s$ — частота дискретизации.

**Значения по умолчанию для разных устройств (при частоте дискретизации 11.52 МГц):**

| Устройство | Значение | Задержка (мкс) |
|------------|:--------:|:--------------:|
| USRP B210 | 100 | ≈ 8.68 |
| bladeRF | 27 | ≈ 2.34 |
| Автоопределение | `auto` | — |

> **Рекомендация:** В большинстве случаев достаточно оставить `time_adv_nsamples = auto`. Если наблюдаются проблемы с синхронизацией (например, UE не может захватить сигнал eNB), попробуйте подобрать значение вручную с шагом 10–20 отсчётов.

### Расчёт частот DL/UL

Если `dl_freq` и `ul_freq` не заданы явно, частоты рассчитываются по номеру EARFCN на основе стандарта 3GPP TS 36.101:

- Для диапазона LTE **Band 1** (IMT-2100):
  - **DL:** $F_{DL} = 2110 + 0.1 \times N_{DL}$ (МГц), где $N_{DL}$ — `dl_earfcn` (0–599)
  - **UL:** $F_{UL} = F_{DL} - 190$ (МГц) — разнос частот (duplex spacing) 190 МГц
- Для диапазона LTE **Band 3** (DCS-1800):
  - **DL:** $F_{DL} = 1805 + 0.1 \times (N_{DL} - 1200)$ (МГц), где $N_{DL}$ в диапазоне 1200–1949
  - **UL:** $F_{UL} = 1710 + 0.1 \times (N_{UL} - 1200)$ (МГц)
- Для диапазона LTE **Band 7** (IMT-E-2600):
  - **DL:** $F_{DL} = 2620 + 0.1 \times (N_{DL} - 2750)$ (МГц), где $N_{DL}$ в диапазоне 2750–3449
  - **UL:** $F_{UL} = 2500 + 0.1 \times (N_{UL} - 2750)$ (МГц)
- Для диапазона LTE **Band 20** (EU Digital Dividend):
  - **DL:** $F_{DL} = 791 + 0.1 \times (N_{DL} - 6150)$ (МГц)
  - **UL:** $F_{UL} = 832 + 0.1 \times (N_{UL} - 6150)$ (МГц)

> Общая формула: $F = F_{low} + 0.1 \times (N - N_{offset})$, где $F_{low}$ — нижняя граница полосы, $N$ — номер EARFCN, $N_{offset}$ — смещение диапазона. Подробнее — 3GPP TS 36.101, Table 5.7.3-1.

> **Примечание:** Рекомендованные значения `device_args` и `time_adv_nsamples` для разных устройств приведены выше в пояснениях к соответствующим параметрам.

### Пояснения к политикам планирования

- **time_rr** (Round Robin): равномерное распределение ресурсов между пользователями поочерёдно.
- **time_pf** (Proportional Fair): компромисс между справедливостью и пропускной способностью, учитывает качество канала каждого пользователя.
- **time_bf** (Best Effort / Blind Fair): аналогичен PF, но с меньшими вычислительными затратами.

### [channel.dl.delay] — Эмулятор задержки

Задержка моделируется как:

$$delay(t) = delay_{min} + (delay_{max} - delay_{min}) \times \frac{1 + \sin(2\pi \cdot t / period)}{2}$$

Максимальная скорость (м/с):

$$v_{max} = \frac{(delay_{max} - delay_{min}) \cdot \pi \cdot 300}{period}$$

| Параметр | Описание | Диапазон | Значение по умолчанию |
|----------|----------|----------|-----------------------|
| `enable` | Включить симулятор задержки. | `true` / `false` | `false` |
| `period_s` | Период изменения задержки (с). | Любое положительное число | `3600` |
| `init_time_s` | Начальное время симуляции (с). | Любое число ≥ 0 | `0` |
| `maximum_us` | Максимальная задержка (мкс). | Любое положительное число | `100` |
| `minimum_us` | Минимальная задержка (мкс). | Любое положительное число | `10` |

## Примечания

1. **Формула EARFCN → частота:** $F = F_{low} + 0.1 \times (N - N_{offset})$ согласно 3GPP TS 36.101.
2. **Адаптивный MCS:** Если `pdsch_mcs` или `pusch_mcs` не заданы (`-1`), eNB использует CQI-отчёты от UE для адаптивного выбора MCS.
3. **MBMS:** При включении MBMS необходимо также заменить `sib.conf` на версию с SIB13.
4. **ZMQ:** Для работы через TCP без реального SDR используйте `device_name = zmq` и соответствующие `device_args`.
