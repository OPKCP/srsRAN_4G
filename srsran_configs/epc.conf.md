## Раздел [mme] — MME (Mobility Management Entity)

В разделе выполняется конфигурирование MME (Mobility Management Entity) — узла управления мобильностью, отвечающего за аутентификацию UE, управление сессиями, хэндовер и пейджинг. MME взаимодействует с eNB через интерфейс S1-MME и с HSS для получения абонентских данных.

| Параметр | Описание | Тип / Диапазон | Значение по умолчанию |
|----------|----------|----------------|-----------------------|
| `mme_code` | 8-битный код MME, идентифицирующий MME внутри группы. | `0x00` – `0xFF` (0–255) | `0x1a` |
| `mme_group` | 16-битный идентификатор группы MME. | `0x0000` – `0xFFFF` (0–65535) | `0x0001` |
| `tac` | 16-битный Tracking Area Code. | `0x0000` – `0xFFFF` (0–65535) | `0x0007` |
| `mcc` | Mobile Country Code — код страны. | `0` – `999` (3 цифры) | `250` |
| `mnc` | Mobile Network Code — код оператора. | `00` – `999` (2 или 3 цифры) | `01` |
| `full_net_name` | Полное отображаемое имя сети. | Строка | — |
| `short_net_name` | Краткое отображаемое имя сети. | Строка | — |
| `apn` | Access Point Name — точка доступа (APN). | Строка (FQDN) | — |
| `mme_bind_addr` | IP-адрес для привязки MME для приёма S1-MME соединений от eNB. | IPv4-адрес | `172.18.0.2` |
| `dns_addr` | Адрес DNS-сервера для UE. | IPv4-адрес | `8.8.8.8` |
| `encryption_algo` | Предпочтительный алгоритм шифрования для NAS-уровня. | `EEA0`, `EEA1`, `EEA2`, `EEA3` | `EEA0` |
| `integrity_algo` | Предпочтительный алгоритм защиты целостности для NAS. | `EIA0`, `EIA1`, `EIA2`, `EIA3` | `EIA1` |
| `paging_timer` | Значение таймера пейджинга (T3413) в секундах. | Целое число ≥ 0 | `2` |
| `request_imeisv` | Запрашивать IMEI-SV у UE в команде режима безопасности. | `true` / `false` | `false` |
| `lac` | 16-битный Location Area Code. | `0x0000` – `0xFFFF` (0–65535) | `0x0006` |

### Пояснения к алгоритмам шифрования и целостности

| Идентификатор | Алгоритм |
|---------------|----------|
| EEA0 | Null — без шифрования |
| EEA1 | Snow3G (128-EEA1) |
| EEA2 | AES (128-EEA2) |
| EEA3 | ZUC (128-EEA3) |
| EIA0 | Null — без защиты целостности (отклоняется большинством UE) |
| EIA1 | Snow3G (128-EIA1) |
| EIA2 | AES (128-EIA2) |
| EIA3 | ZUC (128-EIA3) |

> **Важно:** EIA0 (без защиты целостности) отвергается большинством коммерческих UE. В реальных сетях следует использовать EIA1, EIA2 или EIA3.

## Раздел [hss] — HSS (Home Subscriber Server)

В разделе выполняется конфигурирование HSS (Home Subscriber Server) — базы данных абонентов, хранящей информацию об IMSI, ключах аутентификации и профилях QoS. HSS используется MME для проверки подлинности UE и получения параметров подписки.

| Параметр | Описание | Тип | Значение по умолчанию |
|----------|----------|-----|-----------------------|
| `db_file` | Путь к CSV-файлу с информацией об абонентах (UE). | Строка (путь) | `user_db.csv` |

Формат CSV-файла описан в файле [`user_db.csv.md`](user_db.csv.md).

## Раздел [spgw] — SP-GW (Serving/Packet Gateway)

В разделе выполняется конфигурирование SP-GW (Serving and Packet Data Network Gateway) — объединённого шлюза, обеспечивающего туннелирование пользовательского трафика (GTP-U) и выход UE во внешнюю сеть через интерфейс SGi.

| Параметр | Описание | Тип / Диапазон | Значение по умолчанию |
|----------|----------|----------------|-----------------------|
| `gtpu_bind_addr` | Адрес привязки GTP-U (GPRS Tunneling Protocol — User plane). | IPv4-адрес | `172.18.0.2` |
| `sgi_if_addr` | IP-адрес интерфейса SGi (TUN-интерфейс). | IPv4-адрес | `172.18.0.2` |
| `sgi_if_name` | Имя SGi TUN-интерфейса. | Строка | `srs_spgw_sgi` |
| `max_paging_queue` | Максимальное количество пакетов в очереди пейджинга (на одного UE). | Целое число ≥ 0 | `100` |

> **Примечание:** TUN-интерфейс `sgi_if_name` создаётся автоматически при запуске EPC. Через него осуществляется маршрутизация пользовательского трафика UE во внешнюю сеть.

## Раздел [pcap] — Захват пакетов

В разделе выполняется конфигурирование захвата сетевых пакетов (PCAP) для протокола S1AP. Захваченные пакеты можно анализировать в Wireshark для отладки сигнального обмена между eNB и EPC.

| Параметр | Описание | Тип | Значение по умолчанию |
|----------|----------|-----|-----------------------|
| `enable` | Включить захват пакетов S1AP. | `true` / `false` | `false` |
| `filename` | Путь к файлу PCAP. | Строка (путь) | `/tmp/epc.pcap` |

> **Примечание:** Файлы PCAP декодируются Wireshark с DLT=150, Payload Protocol = s1ap.

## Раздел [log] — Логирование

В разделе выполняется конфигурирование системы логирования EPC. Позволяет задать уровень детализации для каждого компонента MME/HSS/SPGW отдельно, что удобно при диагностике проблем.

| Параметр | Описание | Тип / Диапазон | Значение по умолчанию |
|----------|----------|----------------|-----------------------|
| `all_level` | Уровень логирования для всех слоёв. | `debug`, `info`, `warning`, `error`, `none` | `info` |
| `all_hex_limit` | Лимит шестнадцатеричного дампа (байт). | Целое число ≥ 0 | `32` |
| `filename` | Путь к файлу лога. Может быть `stdout` для вывода в консоль. | Строка (путь) | `/var/log/srsran/epc.log` |

### Слои логирования

`nas`, `s1ap`, `mme_gtpc`, `spgw_gtpc`, `gtpu`, `spgw`, `hss`, `all`

Каждый слой настраивается индивидуально, например:

```ini
nas_level = debug
s1ap_level = debug
mme_gtpc_level = debug
spgw_gtpc_level = debug
gtpu_level = debug
spgw_level = debug
hss_level = debug
```

## Примечания

1. MME, HSS и SP-GW работают в рамках одного процесса `srsepc`.
2. Адреса `mme_bind_addr`, `gtpu_bind_addr` и `sgi_if_addr` могут совпадать (на практике часто все указываются на один IP-адрес EPC).
3. APN (`apn`) должен соответствовать значению, которое UE передаёт в NAS-сообщениях при установке PDN-соединения.
4. Для работы с реальными SIM-картами алгоритмы шифрования EEA1/EEA2/EEA3 должны совпадать с возможностями UE и SIM.
