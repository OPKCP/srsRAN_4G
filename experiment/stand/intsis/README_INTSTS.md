# Стенд srsRAN 4G — работа под пользователем `intsis`

Учётная запись **`intsis`** (пароль `intsis`) предназначена для учебной работы
со стендом. Пользователь **не имеет прав sudo** (в группах только `docker`),
поэтому может запускать и останавливать контейнеры стенда, но не менять
системные настройки.

## Доступ

С домашнего компьютера (ключ уже настроен, пароль не спрашивается):

```bash
ssh pi5-intsis      # 192.168.1.26 — ядро сети, БС2, веб-серверы, мониторинг
ssh base5-intsis    # 192.168.1.25 — БС1 и её дашборд
```

С pi5-2 на base5 (тоже по ключу, без пароля): `ssh base5`.

## Скрипты

Все скрипты лежат в домашнем каталоге; запускать из `~`:

```bash
cd ~
```

| Скрипт | Узел | Что делает |
|--------|------|-----------|
| `./start-all.sh` | **pi5-2** | **Запуск всего стенда**: ядро → веб/мониторинг → БС2 → по ssh БС1 с base5 |
| `./stop-all.sh`  | **pi5-2** | **Остановка всего стенда** (в обратном порядке) |
| `./start-core.sh` / `./stop-core.sh` | pi5-2 | Ядро сети Open5GS + MongoDB |
| `./start-web.sh` / `./stop-web.sh`   | pi5-2 | webserve + дашборды (ядра и БС2) + Prometheus + Grafana |
| `./start-bs.sh` / `./stop-bs.sh`     | pi5-2 | БС2 (eNB2, 1811 МГц) |
| `./start-all.sh` | **base5** | БС1 (eNB1, 1815 МГц) + её дашборд |
| `./stop-all.sh`  | **base5** | Остановка компонентов base5 |
| `./start-bs.sh` / `./stop-bs.sh`     | base5 | БС1 (eNB1, 1815 МГц) |
| `./start-web.sh` / `./stop-web.sh`   | base5 | дашборд БС1 |

**Стенд целиком запускается с pi5-2**: `./start-all.sh` поднимет ядро, серверы,
БС2 и по ssh запустит БС1 с base5. На base5 `./start-all.sh` поднимает только
местные компоненты (БС1 и её дашборд).

Порядок важен: `./start-web.sh` на pi5-2 требует запущенного ядра (webserve
работает в его network namespace), поэтому сначала `./start-core.sh`.

`./start-core.sh` также настраивает **NAT и форвардинг** для абонентской сети
10.0.0.0/24 (MASQUERADE + правила FORWARD) — без этого телефон подключается и
получает адрес, но интернет и доступ к серверам на 10.0.0.1 не работают.
Правила ставятся изнутри контейнера `open5gs` (он в host-сети и имеет
CAP_NET_ADMIN), поэтому `sudo` не требуется.

## Проверка состояния

```bash
docker ps                          # контейнеры этого узла
docker logs -f enb2                # лог БС2 (на base5 — docker logs -f enb)
docker logs -f open5gs             # лог ядра
ssh base5 'docker ps'              # контейнеры base5
```

Признаки успешного запуска:
- в логе БС — `==== eNodeB started ===` и `Setting frequency: DL=...`;
- в логе ядра — `eNB-S1 accepted[...]` и `Number of eNBs is now 2`;
- в выводе `./start-core.sh` — строки с MASQUERADE/FORWARD для 10.0.0.0/24;
- при подключении телефона — `Attach request` и выдача адреса из 10.0.0.0/24.

## Если телефон подключился, но интернета нет

Проверьте NAT и форвардинг (они настраиваются `./start-core.sh`):

```bash
docker exec open5gs iptables -t nat -S POSTROUTING | grep 10.0.0.0/24
docker exec open5gs iptables -S FORWARD | grep -E '10.0.0.0/24|ogstun'
docker exec open5gs ip -4 addr show ogstun        # должен быть 10.0.0.1/24
```

Если правил нет — перезапустите ядро: `./stop-core.sh && ./start-core.sh`.

Если не открывается веб-сервер `http://10.0.0.1:8080`:

```bash
docker exec open5gs curl -s -o /dev/null -w '%{http_code}\n' http://10.0.0.1:8080/
```

Ожидается `200`. `000` сразу после старта — сервис ещё поднимается, подождите
несколько секунд; если не проходит и дальше — перезапустите `./start-web.sh`
(он должен запускаться после ядра).

## Важные ограничения

- **sudo недоступен.** Скрипты специально не требуют root: доступ к SDR обеспечен
  udev-правилом на запись всем, вторичный IP для БС2 прописан в NetworkManager,
  каталоги данных принадлежат нужным uid.
- **Только запуск и остановка компонентов** — системные настройки менять нельзя.
  При необходимости правок обратитесь к администратору стенда.
- **БС1 — клон LibreSDR B220mini** (FPGA Artix-7). Ему нужен свой битстрим
  `~/srsran/uhd_images/usrp_b210_fpga.bin`; при подмене на штатный образ Ettus
  БС падает с `fx3 is in state 5` (скрипт это проверяет и предупреждает).
- **Первый запуск БС после долгого простоя** может занимать несколько минут
  (расчёт FFT-плана в `~/srsran/data/fftw`); далее план переиспользуется.
- **Питание:** при слабом БП возможен троттлинг малинки и нестабильность радио
  (`vcgencmd get_throttled`, `0x0` — норма).
