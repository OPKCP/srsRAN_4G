## Ключевые этапы старта (БС1/БС2)

1. `Using binary srsenb` — инициализация процесса.
2. `Opening 1 channels in RF device` — открытие SDR.
3. `Actually got clock rate 23.04 MHz` — настройка мастера-частоты USRP (быстро, ~5-25 с от старта).
4. **Формирование FFT-плана** — самый длительный этап (CPU-интенсивный), ~3-4 минуты,
   в этот период в stdout srsenb новых сообщений нет (процесс «молчит», активно считает).
5. `RF device 'UHD' successfully opened` → `eNodeB started` → `Setting frequency DL/UL` —
   начало излучения.

## Дополнение (проверка 2026-09-04, БС1+БС2)

Вывод выше про «wisdom не записывается» оказался **ошибочным**. Причина — методология
измерения: файл удалялся, а БС останавливалась принудительно (`docker rm -f`/SIGKILL),
при котором деструктор `__attribute__((destructor)) srsran_dft_exit` в
`lib/src/phy/dft/dft_fftw.c` **не успевает** записать wisdom.

При **штатной** остановке (`docker stop`, SIGTERM) wisdom-файл записывается корректно:

| Параметр | БС1 (base5) | БС2 (pi5-2) |
|----------|-------------|-------------|
| wisdom-файл | `~/srsran/fftw/.srsran_fftwisdom` (4722 б) | тот же путь (4721 б) |
| Старт srsenb | 09:01:09.94 UTC | 08:59:44.18 UTC |
| Излучение (Setting frequency) | 09:01:26.93 UTC | 09:00:09.42 UTC |
| **Тёплый старт (с wisdom)** | **≈ 17 с** | **≈ 25 с** |

**Вывод (уточнённый):** при правильном монтировании `~/srsran/fftw → /var/srsran` и
`-e HOME=/var/srsran` (уже в скриптах) wisdom сохраняется между запусками, и повторный
старт занимает **~20-25 секунд вместо ~4 минут**. Холодный старт (~4 мин) происходит
только при первичном формировании плана (или после удаления wisdom-файла).

**Рекомендации:**
- Останавливать БС только штатно (`docker stop`), НЕ `docker rm -f` при живой eNB —
  иначе wisdom не запишется и следующий старт будет холодным (~4 мин).
- Не удалять `~/srsran/fftw/.srsran_fftwisdom`.
- Такой же помощником-сервисом авто-перезапуск (`--restart unless-stopped`) не мешает:
  Docker останавливает контейнер SIGTERM-ом, деструктор срабатывает.

## Выводы

- **Холодный старт (с формированием FFT-плана) занимает ~3.5–4 минуты** на обеих БС
  (только при отсутствии wisdom-файла).
- Различия между БС1 и БС2 незначительны (~15 с), в пределах погрешности запуска —
  время определяется мощностью CPU и одинаковым образом srsran.
- **FFT-wisdom файл записывается при штатной остановке** и ускоряет повторный старт
  до ~20-25 с. Механизм в `lib/src/phy/dft/dft_fftw.c` работает (макрос
  `FFTW_WISDOM_FILE` задан строковой константой в коде, т.е. всегда активен при FFTW).
- Для ускорения будущих стартов достаточно корректно останавливать БС (SIGTERM), чтобы
  wisdom записался в `~/srsran/fftw/.srsran_fftwisdom` (монтируется в `/var/srsran`).

## Примечания

- Healthcheck контейнера `epc` показывает "unhealthy" — штатно (healthcheck под srsenb,
  для srsepc не применим), на время остановки не влияет.
- После замера БС1 и БС2 остались в рабочем состоянии (излучают на своих частотах).
