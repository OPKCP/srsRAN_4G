# Последовательность запуска сети стенда LTE

## Руководство по развёртыванию и запуску

Данный документ описывает строгую последовательность вызова скриптов запуска на устройствах стенда для поднятия сети. Порядок определяется зависимостями компонентов: сервисы на узле ядра (EPC) запускаются в определённой последовательности, базовая станция (eNB) запускается последней — после готовности ядра и радиоустройства.

## 1. Состав устройств и адресация

| Устройство | Роль | IP-адрес |
|------------|------|----------|
| pi5-2 (192.168.1.16) | Пакетное ядро (EPC) + сервисы | 192.168.1.16 |
| Малинка1 (192.168.1.15) | Базовая станция (eNB) | 192.168.1.15 |
| Административный ПК (192.168.1.10) | Управление, перенос скриптов | 192.168.1.10 |
| Маршрутизатор | Транспортная сеть | 192.168.1.1 |

## 2. Расположение скриптов

**В репозитории** (единый источник): каталог `experiment/`:

- `experiment/run_epc_pi5-2.sh`
- `experiment/asterisk/run_asterisk_pi5-2.sh`
- `experiment/run_webserver_pi5-2.sh`
- `experiment/run_enb_rpi.sh`

**Перенос скриптов на устройства (при необходимости):**

```
# Windows → pi5-2 (ядро)
scp experiment/run_epc_pi5-2.sh experiment/run_webserver_pi5-2.sh \
    experiment/asterisk/run_asterisk_pi5-2.sh infarh@192.168.1.16:/tmp/

# Windows → малинка1 (eNB)
scp experiment/run_enb_rpi.sh shmac@192.168.1.15:/tmp/
```

## 3. Строгая последовательность запуска

### ЭТАП 1 — Подготовка радиоустройства (SDR/USRP) на малинка1

Проверить доступность и живость радиоустройства до запуска eNB:

```bash
# на малинка1 (192.168.1.15)
uhd_find_devices
```

Ожидание: обнаружение устройства (USRP B210). При ответе «No UHD Devices Found» — выполнить программный сброс:

```bash
# определить путь устройства (vendor 2500)
ls /sys/bus/usb/devices/*/idVendor | grep -l 2500
# сброс через authorized
echo 0 | sudo tee /sys/bus/usb/devices/<устройство>/authorized
sleep 4
echo 1 | sudo tee /sys/bus/usb/devices/<устройство>/authorized
uhd_find_devices   # повторная проверка
```

Если сброс не помог — физически переподключить USB-кабель радиоустройства.

### ЭТАП 2 — Запуск ядра сети (EPC) и сервисов на pi5-2

Порядок **обязательный**: сначала EPC (создаёт сетевой namespace), затем сервисы в его namespace.

**Шаг 2.1 — EPC (контейнер `epc`):**

```bash
# на pi5-2 (192.168.1.16)
bash /tmp/run_epc_pi5-2.sh
# либо из репозитория:
#   bash experiment/run_epc_pi5-2.sh
```

Назначение: запуск srsepc, настройка NAT + FORWARD для абонентской сети 10.0.0.0/24, доступность S1 (SCTP 36412) и абонентской сети.

Проверка: MME/SP-GW Initialized в логах.

**Шаг 2.2 — SIP-сервер Asterisk (контейнер `asterisk`):**

```bash
# на pi5-2
bash ~/srsran/asterisk/run_asterisk_pi5-2.sh
```

Назначение: SIP-сервер голосовых вызовов, запускается в сетевом namespace контейнера `epc`. SIP-адрес для абонентов: `10.0.0.1:5060`.

Примечание: запускается **после** `epc` (зависит от его namespace).

**Шаг 2.3 — Веб-сервер раздачи файлов (контейнер `webserve`):**

```bash
# на pi5-2
bash /tmp/run_webserver_pi5-2.sh
```

Назначение: раздача файлов абонентам (например, APK/SIP-клиентов) из каталога `~/srsran/apk-serving/` по адресу `10.0.0.1:8080`. Также в namespace `epc`.

### ЭТАП 3 — Запуск базовой станции (eNB) на малинка1

**Шаг 3.1 — eNB (контейнер `enb`):**

```bash
# на малинка1 (192.168.1.15)
bash /tmp/run_enb_rpi.sh
```

Назначение: запуск srsenb, открытие радиоустройства (USRP), установление S1-связи с ядром (mme_addr = 192.168.1.16), трансляция соты.

Конфигурация: `~/srsran/experiment_enb/enb.conf` (n_prb=15, 3 МГц).

Запускается **последним** — после готовности ядра (EPC) и радиоустройства.

### ЭТАП 4 — Проверка состояния сети

```bash
# S1-связь (малинка1)
grep "S1Setup\|completed successfully" ~/srsran/local/logs/enb*.log | tail

# Состояние контейнеров (pi5-2)
docker ps --format '{{.Names}}\t{{.Status}}'

# Интернет-трафик абонентов (pi5-2)
docker exec epc cat /sys/class/net/srs_spgw_sgi/statistics/rx_packets
docker exec epc cat /sys/class/net/srs_spgw_sgi/statistics/tx_packets
```

Критерии готовности:

1. Контейнеры `epc`, `asterisk`, `webserve` на pi5-2 — статус UP.
2. Контейнер `enb` на малинка1 — статус UP, S1-связь установлена.
3. Радиоустройство передаёт (лампы TX/RX), сота видна на анализаторе спектра и телефоне.

## 4. Схема зависимостей

```
[pi5-2]  EPC (run_epc_pi5-2.sh) ──► сетевой namespace 10.0.0.0/24
           │
           ├──► Asterisk  (run_asterisk_pi5-2.sh) — namespace epc
           └──► webserve  (run_webserver_pi5-2.sh) — namespace epc

[малинка1]  eNB (run_enb_rpi.sh) — USRP + S1 → 192.168.1.16 (после готовности EPC)
```

## 5. Примечания

- Каждый скрипт выполняет `docker rm -f <контейнер>` и запускает новый контейнер с фиксированным именем — исключены конфликты и дубликаты.
- Для полной перезагрузки стенда достаточно выполнить этапы 1-4 в указанном порядке.
- Для остановки сети — выполнить `docker rm -f` контейнеров в обратном порядке: `enb`, `webserve`, `asterisk`, `epc`.
- Все скрипты и конфигурации хранятся в репозитории `experiment/` — единый источник для воспроизводимого развёртывания.
