## 1. Что такое стенд

Стенд — это **настоящая сеть сотовой связи LTE в миниатюре** (пикосота).
Она состоит из трёх частей:

| Часть | Что это | Где «живёт» |
|-------|---------|-------------|
| **Ядро сети** (Open5GS) | «Мозг» сети: регистрирует абонентов, выдаёт им IP-адреса, выпускает в интернет | малинка **pi5-2** (192.168.1.26) |
| **Базовая станция БС1** | Радио №1 на частоте **1815 МГц** | малинка **base5** (192.168.1.25) |
| **Базовая станция БС2** | Радио №2 на частоте **1811 МГц** | малинка **pi5-2** (192.168.1.26) |

Дополнительно на pi5-2 работают **веб-серверы мониторинга** — через них удобно
наблюдать за состоянием сети в браузере.

```
   Ваш компьютер (Windows 11)
              |
              |  Wi-Fi сеть IS-1
              |
    +---------+------------------------------+
    |                                        |
[ base5 ]                             [ pi5-2 ]
 192.168.1.25                         192.168.1.26
  БС1 (1815 МГц)                       Ядро сети
  дашборд БС1 (:5000)                  БС2 (1811 МГц)
                                       дашборд ядра (:5001), дашборд БС2 (:5000)
                                       Grafana (:3000), Prometheus (:9091)
                                       веб-сервер для телефонов (10.0.0.1:8080)
```

> **Важно про БС2.** Для работы каждой базовой станции нужна своя плата
> Software Defined Radio (SDR), подключённая по USB. Если плата от БС2 физически
> отсоединена, БС2 работать не будет — это нормально и не является поломкой.
> Ядро сети и БС1 при этом работают полноценно.

Работы на стенде производятся под специальной учебной учётной записью
**`intsis`** (пароль `intsis`). Она специально ограничена: студент может
запускать и останавливать компоненты стенда (включён в группу `docker`), но
**не может изменить настройки системы** — права администратора (`sudo`) у неё
намеренно отключены.

## 2. Подготовка компьютера (делается один раз)

### 2.1 Проверьте, что вы в нужной сети Wi-Fi

Стенд находится в локальной сети **`IS-1`**. Компьютер должен быть подключён
к ней.

1. Нажмите на значок Wi-Fi в правом нижнем углу панели задач (рядом с часами).
2. Убедитесь, что активна сеть **IS-1**.
3. Если нет — выберите её в списке и подключитесь (пароль у преподавателя).

**Проверка.** Откройте терминал (см. раздел 3) и введите:

```powershell
ping 192.168.1.26
```

Ожидаемый ответ — строки вида `Ответ от 192.168.1.26: число байт=32 время<1мс`.
Если пишет «Превышен интервал ожидания» — вы не в сети `IS-1`.

Для остановки `ping` нажмите `Ctrl + C`.

### 2.2 Установите SSH-ключ (одноразовая настройка)

Чтобы подключаться к стенду **без ввода пароля** каждый раз, нужен файл-ключ.
Возьмите его у преподавателя — это файл **`intsis_stand`** (без расширения) и
парный к нему **`intsis_stand.pub`**.

Настройка состоит из трёх шагов: создать папку, положить туда ключ, записать
настройки подключения.

#### Шаг 1. Создайте папку для ключа

Откройте терминал (раздел 3) и выполните:

```powershell
mkdir -Force "$env:USERPROFILE\.ssh"
```

> Если папка уже была — команда ничего не сломает, просто сообщит об этом.

#### Шаг 2. Положите ключ в эту папку

Скопируйте полученные от преподавателя файлы `intsis_stand` и `intsis_stand.pub`
в папку `C:\Users\<ВашеИмя>\.ssh\`.

Самый простой способ найти эту папку: нажмите `Win + R`, вставьте `%USERPROFILE%\.ssh`
и нажмите `Enter` — откроется нужная папка. Вставьте в неё скопированные файлы.

Проверить результат можно в терминале:

```powershell
dir "$env:USERPROFILE\.ssh"
```

В списке должны быть строки с `intsis_stand` и `intsis_stand.pub`.

> **Важно.** Если у вас уже есть файл настроек `.ssh\config` — **не удаляйте
> его**, просто добавьте в конец текст из шага 3.

#### Шаг 3. Запишите настройки подключения

Откройте файл настроек в блокноте:

```powershell
notepad "$env:USERPROFILE\.ssh\config"
```

Блокнот спросит о создании нового файла — согласитесь («Создать файл»). Вставьте
в него **ровно такой текст** (если файл уже был — допишите в самый конец):

```text
Host pi5-intsis
  HostName 192.168.1.26
  User intsis
  IdentityFile ~/.ssh/intsis_stand
  IdentitiesOnly yes
  StrictHostKeyChecking accept-new

Host base5-intsis
  HostName 192.168.1.25
  User intsis
  IdentityFile ~/.ssh/intsis_stand
  IdentitiesOnly yes
  StrictHostKeyChecking accept-new
```

Сохраните файл (`Ctrl + S`) и закройте блокнот.

#### Шаг 4. Проверка

В терминале выполните:

```powershell
ssh pi5-intsis "hostname"
```

**Ожидаемый ответ:** `pi5-2`. Если пароль не спросили — ключ настроен верно.

> **Упрощённый вариант.** Если преподаватель выдал готовую папку `.ssh`
> целиком — просто поместите её содержимое в `C:\Users\<ВашеИмя>\.ssh\` и
> переходите к шагу 4.

### 2.3 Готовые ярлыки для работы (необязательно)

Для удобства можно положить себе несколько готовых файлов-ярлыков (их выдаст
преподаватель — это файлы `.cmd`). Тогда работу со стендом можно вести
**двойным щелчком мыши**, без ввода команд:

| Файл | Действие |
|------|----------|
| `stand-status.cmd` | Показать состояние стенда |
| `stand-logs.cmd` | Показать ключевые логи стенда |
| `stand-start.cmd` | Запустить весь стенд |
| `stand-stop.cmd` | Остановить весь стенд |
| `stand-web.cmd` | Открыть в браузере все страницы мониторинга |

Но и без них всё делается через терминал — как описано ниже.

## 3. Как открыть терминал

Всё управление стендом выполняется **командами в терминале**. Это нормально,
если вы этого никогда не делали — команды нужно просто копировать.

1. Нажмите **правой** кнопкой мыши по кнопке **«Пуск»**.
2. Выберите в списке **«Терминал»** (или «Windows PowerShell»).
3. Откроется тёмное окно — это и есть терминал.

**Как работать с терминалом:**

- Копировать команду: `Ctrl + C` (выделив текст мышью).
- Вставить команду: `Ctrl + V` или **правый щелчок** мыши.
- Выполнить: `Enter`.
- Ошиблись при вводе — ничего страшного, команда просто не сработает.

> **Важно.** Все команды ниже вводятся **в терминале Windows** (то окно, что вы
> открыли), а не в каком-то другом месте. Строки в блоках кода копируйте
> целиком, вместе с кавычками.

## 4. Как подключиться к стенду

Есть два способа.

### Способ А. Одна команда за раз (проще всего)

В терминале Windows сразу пишете команду, которая выполнится на малинке и
вернёт результат. Например:

```powershell
ssh pi5-intsis "hostname"
```

Ответ: `pi5-2`.

Просто **добавляйте нужную команду в кавычках** после `ssh pi5-intsis`.
Именно так и построены все примеры в этом пособии — цельную команду можно
копировать целиком.

### Способ Б. Зайти «внутрь» малинки

Если хочется выполнить много команд подряд, можно войти в сессию:

```powershell
ssh pi5-intsis
```

Приглашение в терминале изменится, например на:

```text
intsis@pi5-2:~$
```

Это значит, что теперь **все команды выполняются на малинке**, а не на вашем
компьютере. Внутри этой сессии команды вводятся без `ssh` и без кавычек:

```text
./status.sh
```

Чтобы **выйти** обратно на свой компьютер, наберите:

```text
exit
```

и нажмите `Enter`.

> **Совет.** Пока вы учитесь, пользуйтесь **способом А** — меньше шансов
> запутаться, где вы находитесь.

### Узлы (малинки)

| Алиас для подключения | Что это | IP |
|----------------------|---------|-----|
| `pi5-intsis` | Ядро сети, БС2, все веб-сервисы | 192.168.1.26 |
| `base5-intsis` | Базовая станция БС1 | 192.168.1.25 |

**Откуда запускать стенд целиком:** с узла `pi5-intsis`. Его скрипт запуска
сам зайдёт на `base5` и включит БС1.

## 5. Проверка состояния стенда

Проверять состояние можно в любой момент — эта команда **ничего не меняет**,
только показывает.

### 5.1 Полная сводка (рекомендуется)

```powershell
ssh pi5-intsis "./status.sh"
```

Пример вывода, когда всё хорошо:

```text
################################################################
#  СОСТОЯНИЕ СТЕНДА srsRAN 4G
#  Узел: pi5-2 (192.168.1.26)
#  Время: 16.10.2026 18:01
################################################################

=== 1. ЯДРО СЕТИ (Open5GS), узел pi5-2 ===
  [РАБОТАЕТ]   Open5GS (MME/SGW/PGW/HSS)  (контейнер open5gs)
  [РАБОТАЕТ]   MongoDB (база абонентов)  (контейнер open5gs-mongodb)
  --- слушает (нужно для базовых станций) ---
  [OK] S1-MME  (SCTP 36412) — сюда подключаются БС
  [OK] GTP-U   (UDP 2152)   — передача данных абонентов
  [OK] SGi-шлюз абонентов (ogstun): 10.0.0.1/24
  --- подключённые базовые станции (сейчас) ---
  [OK] подключены адреса БС: 192.168.1.20 192.168.1.25
...
```

### 5.2 Как читать результат

| Что видите | Что это значит |
|-----------|----------------|
| `[РАБОТАЕТ]` | Компонент включён — всё хорошо |
| `[ОСТАНОВЛЕН]` | Компонент выключен — если он нужен, запустите стенд (раздел 6) |
| `[ПАУЗА]` | Компонент приостановлен (в таком состоянии радио не работает) |
| `[ОК]` | Проверка пройдена |
| `[ВНИМАНИЕ]` | На что-то нужно обратить внимание — смотрите пояснение в той же строке |

Главное, на что смотреть:

1. **Ядро сети** — должно быть `[РАБОТАЕТ]`, а строки `S1-MME`, `GTP-U` и
   `SGi-шлюз` — с пометкой `[OK]`.
2. **Базовые станции** — `[РАБОТАЕТ]`, и в разделе «подключённые адреса БС»
   должны быть `192.168.1.25` и `192.168.1.20`.
3. **Веб-серверы** — коды `200` (открывается) или `302`.

### 5.3 Короткая проверка (список компонентов)

Команда `docker ps` показывает список работающих частей стенда. Обычный её
вывод очень широкий, поэтому используйте компактный вариант:

```powershell
ssh pi5-intsis "docker ps --format '{{.Names}}  {{.Status}}'"
```

Результат:

```text
enb2                   Up 25 minutes (Paused)
grafana                Up About an hour
prometheus             Up About an hour
srsran-dashboard-enb2  Up About an hour
srsran-dashboard-epc   Up About an hour
webserve               Up About an hour
open5gs                Up About an hour
open5gs-mongodb        Up About an hour
```

**Как читать:** если в статусе есть `Up` — компонент работает. Если `Exited` —
остановлен. Если `(Paused)` — приостановлен (см. раздел 11.7).

То же для второго узла:

```powershell
ssh base5-intsis "docker ps --format '{{.Names}}  {{.Status}}'"
```

Ожидаемый результат — строки `enb` и `srsran-dashboard-enb` со статусом `Up`.

### 5.4 Проверка конкретной станции

```powershell
ssh base5-intsis "./status.sh"
```

Покажет состояние **БС1** (радио №1) и её дашборда.

## 6. Запуск стенда

> **Порядок важен:** стенд запускается **с узла `pi5-intsis`**. Он сам поднимет
> ядро сети, все веб-сервисы, БС2 и по сети включит БС1 на другой малинке.

### 6.1 Запустить весь стенд

```powershell
ssh pi5-intsis "./start-all.sh"
```

**Что произойдёт** (по шагам, займёт от 1 до 5 минут):

1. Запустится ядро сети (Open5GS + база абонентов MongoDB), настроится выход
   абонентов в интернет.
2. Запустятся веб-серверы: дашборды, Grafana, Prometheus.
3. Запустится БС2 на pi5-2.
4. По сети подключится к base5 и запустит БС1.

**Пример успешного вывода** (в самом конце):

```text
=================== СВОДКА ===================
  ядро              : rc=0
  веб и мониторинг  : rc=0
  БС2 (pi5-2)       : rc=0
  БС1 (base5)       : rc=0
==============================================
Состояние контейнеров на pi5-2:
enb2	Up 9 seconds (healthy)
grafana	Up 13 seconds
prometheus	Up 13 seconds
srsran-dashboard-enb2	Up 14 seconds
srsran-dashboard-epc	Up 14 seconds
webserve	Up 14 seconds
open5gs	Up 16 seconds
open5gs-mongodb	Up 18 seconds
[OK] Стенд запущен полностью.
```

**Как понять, что всё хорошо:**

- для всех четырёх пунктов `rc=0` — ошибок нет;
- последняя строка — `[OK] Стенд запущен полностью.`;
- в списке контейнеров у каждого стоит `Up`.

> **Если по какому-то пункту `rc` не равен нулю** — не пугайтесь. Чаще всего это
> означает, что не подключена плата SDR у соответствующей базовой станции (см.
> раздел 11). Ядро сети при этом всё равно поднимется и будет работать.

### 6.2 Запустить только часть стенда

Иногда нужно не всё, а только часть. Скрипты запуска запускаются **с того узла,
где находится нужный компонент**.

**Ядро сети** (только pi5-2):

```powershell
ssh pi5-intsis "./start-core.sh"
```

**Веб-серверы и мониторинг** (только pi5-2; нужно запускать **после** ядра):

```powershell
ssh pi5-intsis "./start-web.sh"
```

**Базовая станция БС2** (на pi5-2):

```powershell
ssh pi5-intsis "./start-bs.sh"
```

**Базовая станция БС1** (на base5):

```powershell
ssh base5-intsis "./start-bs.sh"
```

Или сразу БС1 вместе с её дашбордом:

```powershell
ssh base5-intsis "./start-all.sh"
```

### 6.3 Если первый запуск долгий

При первом включении после долгого простоя малинки пересчитывают таблицу
ускорения расчётов (FFT-план). Это может занять **несколько минут** — нужно
просто подождать. При последующих запусках всё происходит за секунды.

Признак того, что базовая станция действительно стартовала, — строки
`eNodeB started` и `Setting frequency` в её логе (см. раздел 7).

## 7. Проверка, что всё действительно работает (логи)

Запуск без ошибок ещё не значит, что сеть полноценно работает. Убедимся сами.

### 7.1 Главный способ: посмотреть ключевые логи

Для этого есть готовый скрипт — он сам покажет всё важное:

```powershell
ssh pi5-intsis "./logs.sh"
```

**Пример хорошего вывода:**

```text
========= ЯДРО СЕТИ (Open5GS) =========

--- Подключение базовых станций (ожидаем 'Number of eNBs is now 2') ---
10/16 14:52:30.277: [mme] INFO: eNB-S1 accepted[192.168.1.20] ...
10/16 14:52:30.277: [mme] INFO: [Added] Number of eNBs is now 2 ...

--- Абоненты: подключение и выдача адреса (ожидаем IPv4[10.0.0.x]) ---
10/16 14:06:36.379: [upf] INFO: UE ... APN[IS2026.net] ... IPv4[10.0.0.3] ...

--- Ошибки ядра (если пусто — всё хорошо) ---
  (записей нет)

========= БАЗОВАЯ СТАНЦИЯ БС2 (pi5-2) =========

--- Радио и старт (ожидаем 'eNodeB started' и 'DL=1811.0 Mhz') ---
[INFO] [B200] Detected Device: B210
==== eNodeB started ===
Setting frequency: DL=1811.0 Mhz, UL=1716.0 MHz ...

  ошибок радио (Fatal radio error): 0

========= БАЗОВАЯ СТАНЦИЯ БС1 (base5, по сети) =========

--- Радио и старт (ожидаем 'eNodeB started' и 'DL=1815.0 Mhz') ---
==== eNodeB started ===
Setting frequency: DL=1815.0 Mhz, UL=1720.0 MHz ...

  ошибок радио (Fatal radio error): 0

========= ВЕБ-СЕРВЕРЫ =========
  webserve                 running
  ...
  веб-сервер стенда для телефона (10.0.0.1:8080), код ответа:
    200
```

**На что смотреть:**

| Что ищем | Хороший признак | Что означает |
|----------|----------------|--------------|
| `Number of eNBs is now 2` | есть | **обе** базовые станции подключились к ядру |
| `eNodeB started` + `Setting frequency` | есть у БС1 и БС2 | радио запустилось, указана рабочая частота |
| `IPv4[10.0.0.x]` | есть | абонент (телефон) зарегистрировался и получил адрес |
| `Ошибки ядра` | `(записей нет)` | критичных ошибок нет |
| `Fatal radio error` | `0` | радио работает без сбоев |
| код ответа веб-сервера | `200` | веб-сервер стенда работает |

> Если в разделе «Абоненты» пока пусто — это нормально, пока к сети не
> подключён ни один телефон (см. раздел 8).

### 7.2 Только логи базовой станции БС1

```powershell
ssh base5-intsis "./logs.sh"
```

### 7.3 Сводная проверка

Проще всего ещё раз выполнить:

```powershell
ssh pi5-intsis "./status.sh"
```

и убедиться, что в разделе «подключённые адреса БС» перечислены `192.168.1.25`
и `192.168.1.20`.

### 7.4 Если хочется посмотреть «сырой» лог

Полные логи компонентов можно вывести вручную. Например, лог ядра:

```powershell
ssh pi5-intsis "docker logs --tail 50 open5gs"
```

Лог БС2:

```powershell
ssh pi5-intsis "docker logs --tail 50 enb2"
```

Лог БС1:

```powershell
ssh base5-intsis "docker logs --tail 50 enb"
```

Первые строки этого лога — служебные сообщения драйвера радио, это нормально.
Ищите строки `eNodeB started` и `Setting frequency`.

## 8. Подключение телефона и проверка сети

Стенд создаёт настоящую сеть LTE с именем **IS2026**.

### 8.1 Подключить телефон

1. Возьмите телефон с установленной **специальной SIM-картой стенда**.
2. В настройках телефона → «Мобильная сеть» → **выберите сеть IS2026**
   (или включите «Автоматический выбор сети»).
3. Дождитесь, что телефон покажет подключение к сети (значок 4G/LTE).

### 8.2 Проверить, что абонент зарегистрировался

Посмотрите логи стенда (раздел «Абоненты»):

```powershell
ssh pi5-intsis "./logs.sh"
```

Хороший результат в разделе «Абоненты: подключение и выдача адреса»:

```text
... Attach request ...
... [emm] INFO: [250630000000004] Attach complete ...
... [upf] INFO: UE IMSI[250630000000004] APN[IS2026.net] ... IPv4[10.0.0.3] ...
```

Запись **`Attach complete`** и **`IPv4[10.0.0.x]`** означают, что абоненту
**выдан IP-адрес** и он успешно вошёл в сеть.

### 8.3 Проверить интернет

На телефоне **отключите Wi-Fi** (важно — иначе будет использоваться Wi-Fi, а
не сеть стенда) и откройте любой сайт в браузере.

Если интернет не работает, хотя телефон подключился, см. раздел 11.3.

### 8.4 Проверить отладочный веб-сервер стенда

На стенде работает учебный веб-сервер, доступный **с телефона**:

1. На телефоне (уже подключённом к сети IS2026) откройте браузер.
2. Введите адрес: **`http://10.0.0.1:8080`**

Должна открыться страница стенда. Здесь же доступен тестер качества связи:
**`http://10.0.0.1:8080/tester.html`**

> Адрес **10.0.0.1** — это «шлюз» абонентской сети, он работает **только с
> телефона** внутри сети стенда. С компьютера он недоступен.

## 11. Типичные проблемы и что делать

### 11.1 «При подключении спрашивает пароль» или «Permission denied»

**Причина:** не настроен SSH-ключ.

**Что делать:** вернитесь к разделу 2.2 и выполните настройку. Быстрая проверка:

```powershell
ssh pi5-intsis "hostname"
```

Должно ответить `pi5-2` без запроса пароля.

Дополнительно проверьте, что вы в сети `IS-1`:

```powershell
ping 192.168.1.26
```

### 11.2 «БС2 не запускается, пишет про USRP»

**Причина:** к малинке pi5-2 **не подключена плата SDR** (Software Defined
Radio). Такое бывает, если плату временно забрали для другой работы.

**Сообщение выглядит так:**

```text
[ОШИБКА] USRP не обнаружен (VID 2500 2505 3923) — БС2 НЕ запускается.
         Проверьте подключение платы (USB-порт/кабель).
```

А в самой сводке запуска вы увидите:

```text
  БС2 (pi5-2)       : rc=2
```

и в конце:

```text
[ВНИМАНИЕ] не все компоненты поднялись — см. вывод выше.
```

**Что делать:**

- Это **не поломка** и **не ваша ошибка**. Ядро сети и БС1 продолжают работать.
- Если БС2 нужна — проверьте, подключена ли плата (серебристая коробочка с
  антенной) к USB-порту малинки, и позовите преподавателя.
- Стендом можно пользоваться и без БС2: телефон будет регистрироваться через
  БС1.

Проверить самому, есть ли плата:

```powershell
ssh pi5-intsis "lsusb | grep -i 2500"
```

Если ответ пустой — платы нет. Если увидите строку с `USRP B210` — плата на
месте.

> **Совет.** Тот же признак виден в `./status.sh`: строка
> «на pi5-2 SDR-плата НЕ обнаружена — БС2 запустить нельзя».

### 11.3 Телефон подключился, но интернета нет

**Причина 1 (самая частая):** включён Wi-Fi. Отключите Wi-Fi на телефоне —
трафик должен идти через сеть стенда (LTE).

**Причина 2:** не настроен выход в интернет. Проверьте:

```powershell
ssh pi5-intsis "docker exec open5gs iptables -t nat -S POSTROUTING | grep 10.0.0.0/24"
```

Должна появиться строка со словом `MASQUERADE`. Если её нет — перезапустите
ядро:

```powershell
ssh pi5-intsis "./stop-core.sh"
```

```powershell
ssh pi5-intsis "./start-core.sh"
```

### 11.4 Не открывается веб-сервер `10.0.0.1:8080` с телефона

**Причина 1:** веб-сервер не запущен или запущен раньше ядра.

Порядок важен: сначала ядро, потом веб-серверы. Проверьте и при необходимости
перезапустите:

```powershell
ssh pi5-intsis "./start-core.sh"
```

```powershell
ssh pi5-intsis "./start-web.sh"
```

**Причина 2:** на телефоне включён Wi-Fi. Отключите его.

Проверка со стороны стенда (должен быть код `200`):

```powershell
ssh pi5-intsis "docker exec open5gs curl -s -o /dev/null -w '%{http_code}' http://10.0.0.1:8080/"
```

### 11.5 Не открывается дашборд в браузере

1. Проверьте, что компьютер в сети `IS-1` (`ping 192.168.1.26`).
2. Проверьте состояние:

   ```powershell
   ssh pi5-intsis "./status.sh"
   ```

   В разделе «доступность в браузере» смотрите коды. Если код `000` или «нет
   ответа» — соответствующий сервис ещё поднимается (подождите несколько
   секунд) либо не запущен (запустите `./start-web.sh`).
3. Проверьте, что адрес введён точно: **`http://`**, а не `https://`.

### 11.6 «Стенд запустился, но БС не подключается к ядру»

Признак: в `./status.sh` в списке подключённых БС не хватает нужного адреса.

**Что делать:** перезапустите соответствующую базовую станцию.

Для БС1:

```powershell
ssh base5-intsis "./stop-bs.sh"
```

```powershell
ssh base5-intsis "./start-bs.sh"
```

Для БС2:

```powershell
ssh pi5-intsis "./stop-bs.sh"
```

```powershell
ssh pi5-intsis "./start-bs.sh"
```

### 11.7 Компонент в состоянии `[ПАУЗА]`

Состояние «пауза» означает, что контейнер приостановлен вручную
(`docker pause`). **Радио в таком состоянии не работает.**

Так выглядит, например, остановленная на паузу БС в списке компонентов:

```text
enb2                   Up 26 minutes (Paused)
```

**Что делать:** остановите и запустите компонент заново. Скрипт остановки сам
снимает паузу, после чего запуск проходит нормально:

```powershell
ssh pi5-intsis "./stop-bs.sh"
```

```powershell
ssh pi5-intsis "./start-bs.sh"
```

> **Важно.** Плату SDR нельзя «вынуть из-под работающего радио»: если снять
> контейнер с паузы, когда плата уже отключена, БС упадёт с ошибкой. Поэтому при
> отсутствии платы оставляйте БС в состоянии `[ОСТАНОВЛЕН]` или `[ПАУЗА]`.

### 11.8 Ничего не помогает

Соберите информацию и позовите преподавателя. Выполните:

```powershell
ssh pi5-intsis "./status.sh"
```

и

```powershell
ssh base5-intsis "./status.sh"
```

Покажите распечатку — по ней видно, какой именно компонент не работает.

## Приложение. Мини-словарь

| Слово | Простыми словами |
|-------|------------------|
| **Терминал** | Окно, куда вводят команды текстом |
| **SSH** | Способ подключиться к другому компьютеру по сети и работать на нём |
| **Контейнер** | «Коробка» с программой, изолированная от остальной системы. Все части стенда запущены в контейнерах |
| **Docker** | Программа, которая этими контейнерами управляет |
| **Ядро сети** | Управляющая часть сотовой сети: регистрация абонентов, IP-адреса, выход в интернет |
| **Базовая станция** | Радиочасть: создаёт сеть LTE, к которой подключается телефон |
| **SDR / USRP** | Плата, подключённая по USB, которая превращает компьютер в радиостанцию |
| **Скрипт** | Файл с набором команд; запускается одной командой (`./start-all.sh`) |
| **sudo** | Права администратора. У учебной учётной записи их нет — это сделано специально |

---

> **Помните:** вы можете **запускать, останавливать и смотреть состояние**
> стенда. Изменять системные настройки малинок нельзя — для этого нужны права
> администратора, которых у учебной учётной записи нет.
